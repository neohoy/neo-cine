# neo/: NEO's own tools

*中文版：[README.zh-CN.md](README.zh-CN.md)*

`core/` is an unmodified mirror of Lemo-Opuscar's tools and is never edited here (see [UPSTREAM.md](../UPSTREAM.md)). Tools that NEO-Cine adds go in this folder, so a sync with upstream can never overwrite them.

- `publish.sh`: uploads the demo films and their 720p web cuts to the repository's releases, for the gallery ([MAINTAINING.md](../MAINTAINING.md), "Publish").
- `geo/osm.py`: turns OpenStreetMap into one JSON file a film page can draw (coast closed into land, water, woods, peaks, roads, railways, buildings, place names; metres around an origin, lines simplified). The City Skyline styles use it; usage is at the top of the file and in [`styles/atlas-scroll/STYLE.md`](../styles/atlas-scroll/STYLE.md) §9 and §10. Data © OpenStreetMap contributors, ODbL 1.0.
- `geo/ohm.py`: the same for OpenHistoricalMap, with dates: borders, railways and named routes, each with the first and last year it existed, so a page can draw the map of any year. Give it the same `--origin` and `--proj` as the `osm.py` file it is drawn over. Used by [`styles/atlas-scroll`](../styles/atlas-scroll/STYLE.md). Data CC0.
- `geo/routes.py`: public-transport routes from OpenStreetMap (route relations: subway, train, tram, bus, ferry…) → one JSON file: each route's ways stitched into one path in the direction of travel, its stops in order with their distance along the path, its ref, name and published colour, the route_master groups, and the stops merged into stations. Same `--origin` and `--proj` as an `osm.py` file to overlay it. Usage at the top of the file; used by the Transport styles. Data © OpenStreetMap contributors, ODbL 1.0.
- `geo/buildings.py`: real building footprints and heights for a box → one JSON file a page can extrude: OpenStreetMap through Overpass (names, types, `building:part` towers and podiums with `min_height`, courtyards) merged with the buildings theme of Overture Maps (GeoParquet on Overture's public S3 bucket or its Azure mirror, the latest release found in its STAC catalogue, read by bbox), which adds the machine-detected footprints OSM lacks. Overture rows that came from OSM are matched by id and dropped; other footprints are added unless they overlap an OSM building. Every building says where its height came from: `measured` (a height tag), `levels` (floors × 3.2 m) or `estimated` (nearby buildings of a similar size, capped at 60 m, else a default by type). Same `--origin` and `--proj` as `osm.py`; raw answers cached in `<out>.cache/`, so a second run is offline. The Overture source needs `duckdb` ([`requirements-geo.txt`](requirements-geo.txt)); `--sources osm` needs nothing. Used by [`styles/folding-city`](../styles/folding-city/STYLE.md). Data: OpenStreetMap © OpenStreetMap contributors, ODbL 1.0; Overture buildings theme ODbL 1.0 (Overture Maps Foundation), whose sources ask for their own credit (Microsoft and Google building footprints, Esri Community Maps, Shi et al. 2023 for East Asia, CC BY 4.0, …): the file's `meta.sources` names the ones it contains; the full list is at the top of the script.
- `geo/gtfs.py`: a GTFS timetable (the format operators publish) → the trips that run on one day, filtered by agency, route, route type, a box or the stops a trip must call at, grouped into stop patterns with their departures. Stop times the feed leaves blank are interpolated by distance and marked; headway-based trips (`frequencies.txt`) are expanded and marked. The feed's licence is its publisher's: name it in `CREDITS`. Used by the Transport styles.
- `render/remote.sh` (with `render/frames.mjs`): renders a page on another machine with a GPU, over ssh (the owner's Windows desktop: `NEO_RENDER_HOST`, default `render`), with the same page contract and the same encode as `core/render/video.mjs`, and brings back the video, or stills with `--times`. Nothing is installed there beyond Node and ffmpeg: the runtime (`core/`, three, playwright-core, `frames.mjs`) is sent once and again only when it changes; each render sends the demo folder to its own job folder and deletes it afterwards. A demo's `build.sh` uses it with `RENDER=remote`.
- `audio/master.py`: the last step of a film's `mix.py`. It brings the mix to −14 LUFS with one gain for the whole film and shortens only the peaks (a soft clip, then a true-peak limiter), so the loudnorm pass in `mux.sh` has nothing left to reshape; `check()` measures the written mix the way `mux.sh` does and fails the build when loudnorm would have to ride the level. The reason and the numbers to read are at the top of the file. Used by the `mix.py` of every demo (for example [`styles/atlas-scroll`](../styles/atlas-scroll/demo/mix.py)).
- `audio/cues.py`: lets a film's `mix.py` read the picture's events by name and checks that the score lands on them. Sounds driven by the picture take their time from the event; an accent written on the music grid names the event it belongs to; `report()` prints every cue with the distance between score and picture and fails the build when one is more than half a frame off. It works from `events.json` alone, so any style can use it. Used by the `mix.py` of every demo (for example [`styles/atlas-scroll`](../styles/atlas-scroll/demo/mix.py)).
