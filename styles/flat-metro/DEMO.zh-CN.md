## 故事与结构

同一张图、同一分钟、两个夜晚：周四凌晨一点半，维也纳地铁睡了；周五凌晨一点半，它还在跑。

- **铺垫（0–9 秒）。** 夜色的底上，多瑙河是一片平涂的水；U1 从 Oberlaa 被拉出真实轨道，镜头贴着那只手；线在手后面收紧成 45° 的台阶，越过多瑙河。U6、U4、U2、U3 接着被拉出来，越来越快，镜头拉回整张网。片名：凌晨一点半 / Half Past One。
- **转折（9–27.75 秒）。** 周四 23:20 → 01:00，大约 8 分钟一秒：列车滑行、减速进站；00:47 到 01:00 之间，每条线的末班车开到终点，这条线就退进底色。01:30 什么都不跑了，钟几乎停住（字幕：五条线都停了）。然后底色沿 45° 扫过整整一天，跟着维也纳真实的太阳，钟落在周五夜里。
- **结尾（27.75–57 秒）。** 周五 00:13 → 01:30：过了一点，线还亮着，车还在来。镜头推进内城，钟慢到接近真实速度：01:30，线上 21 列车。结论：周五、周六夜里，整夜每 15 分钟一班。镜头拉回，钟一路走到周六早上；底色亮成白天，白天的班次回来，片尾卡在整张网旁边。

用到的原生动作：拉线（开场）、线休息（周四）、底色就是钟（一天过去、天亮）、计数（周五 01:30）、推到一站（内城）。

## 配乐结构

80 BPM（一小节 3 秒），F 利底亚，原创；颤音琴、毛毡槌木琴、正弦低音、气声长音、刷子。

- **0–8 秒**：每条线被拉出时一道"嘶"和一个颤音琴音（U1 C5、U6 E5、U4 G5、U2 A5、U3 C6）；每个站孔一下这条线音高的毛毡轻点，换乘站低一点，线收紧时一声轻"嗒"。
- **8.25 秒**：片名：低音 F，一个展开的 Fmaj7。
- **9–18.2 秒**：颤音琴八分音符琶音，F–G–Am–C，低音在小节线上；琶音的声部数 = 还亮着的线的条数，每辆末班车到站就少一个声部（17.1–18.0 秒，每条线两个往下的音）。
- **20.2–24 秒**：近乎静场：只有城市的空气，读"五条线都停了"。
- **24 秒**：一天过去：颤音琴三个八度的上行和一道长"嘶"；**27.75 秒**周五的和弦。
- **29.25–38.25 秒**：琶音回来，五个声部都在，加刷子；**36 秒**在周四变薄的地方，一层气声长音。
- **39–43.5 秒**：音乐退出；只剩列车减速进站的毛毡轻点，近景里更清楚。
- **43.5 秒**：结论，全片最重的和弦（F–C–E–A–B–E，低音 F，一下轻的闷击）。
- **46.5–51 秒**：早上的班次回来，拍子细分成十六分；**51 秒**最后一个和弦，气声长音一直到结束。
- `mix.py` 打印的电平（RMS）：配乐约 −20.0 dB，混响 −27.8，拟音 −34.9，空气 −37.8；`neo/audio/master.py` 用一个增益把混音带到 −14 LUFS（软削波：2% 的窗口被削超过 1 dB）。`neo/audio/cues.py` 对着画面核对 8 个卡点，全部 0 毫秒；483 个声音由画面事件驱动；`mux.sh` 实测 −13.8 LUFS，响度范围 9.1 LU，峰值 −1.7 dBFS。

## 配色与道具

STYLE.zh-CN.md §3 的配色就是本片的；底色跟着维也纳 11 月下旬的太阳走。线路颜色取自 GTFS：U1 `#E3000F`、U2 `#A862A4`、U3 `#EF7C00`、U4 `#319F49`、U6 `#9D6830`。99 个站，105 段；两段画成一个折弯；站位离真实位置平均 270 米（最多约 1 公里，Heiligenstadt）。三个运营日里留下 931 趟班次（片子出现的时段）。地图范围：东经 16.16–16.60°，北纬 48.09–48.33°，北朝上，不画任何界线；宽不到 60 米的溪流不画。

## 构建说明

| 文件 | 画什么 / 做什么 |
|---|---|
| `demo/index.html` | 字体和画布 |
| `demo/timeline.js` | 唯一的时间来源：`CLOCK`、`CAM`、`DRAW`、`FOLLOW`、`PASS`、`CAPS`、`END`、`SECS` |
| `demo/flat.js` | 画法：底色和太阳、派生的颜色、线、站孔、换乘钉、列车方块、钟的数字 |
| `demo/main.js` | 数据 → 线、站、班次；拉线；镜头；列车；站名；文字栏；片尾卡；声音事件；`window.render` |
| `demo/mix.py` | 配乐、拟音、空气、卡点核对和母带 |
| `demo/tools/prep.py` | OSM + GTFS → `data/net.json`（八方向布局、色块、班次、运营时段） |
| `demo/tools/fonts.sh` | 下载字体 |
| `demo/build.sh` | 按顺序做完所有步骤 |

- 构建：`sh styles/flat-metro/demo/build.sh vNNN`（字体 → 没有 `net.json` 时准备数据：Overpass 取 OSM，GTFS 压缩包（约 100 MB）放进 `data/gtfs.cache/`，`neo/geo/gtfs.py` 读三个运营日，`prep.py` → 事件 → 混音（含卡点和电平检查）→ 24 fps 画面 → 检查有没有崩溃的白帧 → 合成，−14 LUFS，BT.709，不加颗粒 → 阅读时长检查 → 55 秒的海报、41 秒的风格帧）。`RENDER=remote` 用 `neo/render/remote.sh` 在渲染机上渲染画面（4 个 worker）。每次构建都是新版本，不覆盖任何东西。
- 渲染时间：渲染机（RTX 4060 Ti，4 个 worker）1,368 帧 27 秒，连同在那边编码 50 秒；远程这一步连传输约 57 秒；整个构建约 1.5 分钟（混音约 3 秒，合成约 17 秒，阅读检查约 3 秒）。
- 检查：每 2.5 秒一帧；拉线（0–4 秒）和推进（36–40 秒）按 0.2 秒一帧看；多瑙河的几处过河放大看。
- 本片的坑：
  - GTFS 每站只给一个时刻：在每个公开时刻之前假设停站 20 秒，片尾卡写明位置是推算的。
  - 周五夜里的列车属于周六的运营日（00:10 起）：周五夜里是用两个运营日拼出来的。
  - 一开始用截取过时段的班次判断"线亮不亮"，白天那一段就错了；现在用三天全部班次算出的运营时段。
  - 开场近景（放大超过 2 倍）时内城站名先冒了出来：现在要等所有线都收紧后才出现。
  - 第一次远程试渲的静帧是一张白图（浏览器标签页崩溃，`neo/render/frames.mjs` 检测不到）：`build.sh` 现在发现整段纯白就停下。
