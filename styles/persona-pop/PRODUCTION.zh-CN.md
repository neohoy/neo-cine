# 拟人 MV Persona Pop — 制作手册

*本文是 [PRODUCTION.md](PRODUCTION.md) 的中文版，以英文版为准。*

这种风格的片子只用本库就能做完：[`kit/`](kit/) 里的工具包（播放整片的页面，以及出角色图、排歌词、切字体、做声音的工具），加上库里的 `core/` 和 `neo/`。画风和规矩在 [`STYLE.zh-CN.md`](STYLE.zh-CN.md)；这份是工作顺序。对这种风格，它代替 AGENTS.md 里的方案和分镜两步，有三处要用户确认（这是风格的一部分，不能省）：角色、梗表、成片。

所有命令都在库的根目录跑（技能模式下是 `$LIB`）。`<P>` 是这支片的工程目录（AGENTS.md 的"文件放在哪"）。`K=styles/persona-pop/kit`，`PY=.venv/bin/python`。

## 0. 需求

请求里没说的，一次问清：

- **角色是谁：** 两个（最多三个），每人在这件活里有个角色（"想得多的那个""跑得快的那个"）、一种标志色，以及是否代表某个真实产品。代表真实产品时，这就是一支非官方同人片：告诉用户，不画它的标志和界面，署名里写明。
- **演的是什么活：** 故事的每一句，最好已经是歌词（6–12 句短句，每句 4–8 个字）。
- **歌：** 用户自己的（mp3、wav 或 m4a，带逐句时间：生成歌曲的平台给的 LRC 最好），或者没有（工具包写伴奏，再写一条替歌词唱的主旋律）。
- **长度和画幅：** 30–60 秒，默认 9:16（1080×1920）。
- **生图工具：** `$PY core/image/gen_image.py --check`（已登录的 Codex CLI）；不行就用用户自己的工具，提示词按第 2 步来。

## 1. 建工程

先把示范片的四个文件复制到 `<P>/` 当起点：`styles/persona-pop/demo/` 下的 `mv.json`、`cast.json`、`index.html`、`scenes.js`，再清空 `sheet`、`make` 和各段。`index.html` 和 `scenes.js` 里的引用是绝对路径（`/styles/persona-pop/kit/page/…`），放在哪个目录都能用。

| `mv.json` 字段 | 含义 |
|---|---|
| `name`、`title` | 文件名前缀（`<name>-v001.mp4`）、片名 |
| `fps`、`dur`、`size` | 30、片长（秒）、`[1080, 1920]` |
| `bpm`、`grid` | 速度；排字的网格（秒，0.25 = 120 BPM 的八分音符） |
| `sections` | `[{id, t, bars}]`：前奏、主歌、副歌、尾声……（从歌里读，或者自己定） |
| `sheet` | 歌词，一句一项（格式见 `kit/tools/grid.py`） |
| `score` | 没有歌时：每段的 `chords`（MIDI 三和弦，或者写另一段的名字）和 `drums`（`none`、`half`、`full`、`hit`） |
| `audio`、`audio_t0` | 有歌时：`<P>/audio/` 里的文件，以及片子第 0 秒对应歌的第几秒 |
| `poster`、`hud` | 海报取片中第几秒；进度 HUD 上的字（`false` 就不要进度条） |

## 2. 角色（用户确认）

1. 在 `cast.json` 里写每个角色的 `look`（年龄、发型、脸、服装、一件道具、一个性格），以及共用的 `style`（画风；背景句由 `cast.py` 加：默认透明底，出不了透明底的工具写 `"bg": "magenta"`）。
2. 在 `make` 里列出姿势：先出定妆图（正面、自然），再出歌词需要的姿势（思考、干活、慌张、欢呼、结尾定格），每个角色再加 2–3 张胸部以上特写。第一张之后的每个姿势，`ref` 里都放定妆图。
3. 每个唱自己那句的特写，在 `make` 里加一张口型表：`"grid": [2, 2]`，四个 `cells`（`<角色>-cu-<姿势>-m`、`-a`、`-o`、`-b`），`ref` 放那张特写，提示词写明除了嘴和眼睛都不变（闭嘴、"啊"、"哦"、眨眼）。四格的名字也加进 `images`。
4. `$PY $K/tools/cast.py <P>`（或者加 `--dry` 打出提示词，交给别的工具），再 `$PY $K/tools/key.py <P>`。看它的报告：头没找到的那张按包围盒放（看一眼，走样就重出）；头到脚偏短的姿势是跳、蹲或坐：跳起来的在 `make` 里写 `"lift"`（报告给了参考值），再跑一次 `key.py`。
5. 把所有抠图按 `assets/chars/meta.json` 的真实比例并排放在深色底上，口型表的四格排一行，给用户看。**用户确认角色**之后才开始做场景；走样的姿势重新生成，不要拿去做动画。

## 3. 歌和逐字时间

- **没有歌：** 在 `sheet` 里写每句的起点（`at`，落在拍上）和可选的 `rhythm`，跑 `$PY $K/tools/grid.py <P>`。哪一句最后一个字离这句结束不到 0.3 秒，它会拒绝。
- **用户的歌：** 放进 `<P>/audio/`，填好 `audio`，从歌里读出段落（手账歌谣的 `styles/scrapbook-song/kit/tools/analyze.py` 会打印拍点和重拍）。用 faster-whisper（配音那一档，TECHNIQUE.md §4）从人声取逐字时间，混音太满就先分离人声，存成 `<P>/data/words.json`（`[{"w": "需", "t": 4.02}, …]`，按顺序一个字一项）。`grid.py <P> --words <P>/data/words.json` 会和 `sheet` 逐字对，遇到第一个对不上的字就停：手工改歌词或时间。

## 4. 梗表（用户确认）

每半句歌词一行：时间、谁唱、证明这句话的界面梗、镜头（全身、特写、分屏、漫画分格、底色）、姿势、它的声音、要不要砸字。标出唯一一处冻结和几处冲击帧。**用户确认这张表**，它就是方案。

## 5. 场景

按梗表写 `scenes.js`：每 4 秒（或每句）一段，`html` 用 `kit/page/persona.js` 的元件拼（唱歌的特写用 `cu(…, {mouth: true})`），`build(c)` 里写动作（那个镜头里加 `c.sing(id, who, t0, t1, {blinks})`），动作没登记的声音用 `c.hit()` 补上。新的声音类型要加进 `kit/tools/mix.py` 的 `SOUND` 表（或者改成已有的名字）。要读的字标 `data-read`，当纹理的字标 `data-pass`。片子自己的卡片样式写在 `index.html` 里。

边做边看样帧：`node core/render/still.mjs <P> 5 9.5 18 --size 1080x1920 --out <P>/out/stills`。

## 6. 构建

```sh
sh $K/tools/make.sh <P> v001
```

逐字时间 → 抠图（只处理新的）→ 字体子集（缺字就停）→ 事件 → 混音（伴奏和主旋律，或用户的歌；按事件出音效；卡点核对；−14 LUFS）→ 渲染 → 合成（BT.709，不加颗粒）→ 1080×1920 下的读字检查 → 海报。每次都是新版本，已有的版本号会被拒绝。

## 7. 审片和交付（用户确认）

- 每 1.6 秒一帧的接触表（`still.mjs --range 0.6:<片长>:1.6`，再用 `core/render/sheet.py`），看两遍：一遍看脸和字，一遍看拍子。
- 关卡：`mix.py` 的卡点表（每个重音 0 毫秒）、`master.py` 的检查、`mux.sh` 在 −14 LUFS 且没有警告、读字检查通过。听一下冻结那一段：必须是安静的。
- 按 DIRECTOR.md §11 交付：`<name>-vNNN.mp4`、`poster-vNNN.jpg`、工程目录和署名（角色图用的工具和 `cast.json` 里的提示词、字体、歌的所有者，以及同人片说明，如果有的话）。
