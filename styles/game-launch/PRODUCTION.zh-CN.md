# 游戏发布：制作手册

*英文版：[PRODUCTION.md](PRODUCTION.md)（代理读英文版）*

这个风格的片子怎么从用户带来的东西做出来：**一款游戏的素材：实机录像、截图、主视觉、Logo、立绘、商店页的文字和原声**，只用库里的东西：[`kit/`](kit/) 里的工具包，加上库的 `core/` 和 `neo/` 工具。画面和规则在 [`STYLE.zh-CN.md`](STYLE.zh-CN.md)；这一份是做事的顺序。对这个风格来说，它替代 AGENTS.md 里"处理方案"和"分镜"两步：`STORY.md` 里的三个故事方案和 `game.json` 里的镜头表就是处理方案，要用户确认。**下面三个确认点是风格的一部分，不能省**：故事和镜头表、样张、请用户完整看一遍听一遍。

所有命令在库的根目录跑（技能模式是 `$LIB`）。`<P>` 是片子的工程目录（AGENTS.md "Where things go"：克隆模式是 `films/<名字>/`，技能模式是用户文件夹下的 `<名字>/`；绝不放在 `styles/` 里）。`K=styles/game-launch/kit`。Python 用库的 `.venv/bin/python`（`PY`）。不用 HyperFrames、不用 GSAP、不用 `<video>` 播放：录像由工具包自己切成帧。

## 硬规矩

1. **素材是游戏的。** 只用用户自己的游戏，或者用户已获开发者授权的游戏（要问；DIRECTOR.md §12）。`CREDITS` 写明录像、美术、音乐属于谁。
2. **不编。** 画面上的每个数字、功能和说法，要么录像里看得见（附时间码），要么商店页、更新日志、开发者的帖子里写着（附原话），都记在 `<P>/FACTS.md`。构建会列出不在表里的数字。
3. **实机画面铺满全画面**，字幕牌用游戏 UI 的材质，高潮是一个真实数字或一次真实的爽点，切点在游戏原声的拍上（STYLE.md §1）。
4. **每一帧都是时间的函数；第 0 帧是一张完整的画面。**
5. **不需要任何账号**：配乐是游戏自己的，音效是代码合成的，默认没有旁白。

## 0. 简报

请求里没说的，问一次（AGENTS.md Workflow）：

- **素材**：一个文件夹，里面有实机录像（最好有几分钟的真实游玩，1080p 以上；带黑边的录屏也行）、主视觉、Logo（有透明底的 PNG 最好）、立绘或截图，以及商店页的文字（简介、更新日志、开发者的话）或它的网址。
- **使用权**：游戏是他的，或者开发者已经授权（授权做什么：这支宣传片、社媒发帖）。
- **片子宣布什么**：Demo、抢先体验、发售日、一次更新；在哪个商店、搜什么字；哪些平台。
- **长度**（默认 30–45 秒）、音乐（默认用录像里游戏原声的一段，或者用户给的游戏音乐文件），以及必须出现的东西。

画面是 1920 × 1080，帧率跟录像（默认 30 fps）。

## 1. 建工程、盘点素材：`inventory.py`

```sh
$PY $K/tools/new_project.py <P> --from <素材文件夹> --title 游戏名 [--name 文件名前缀]
```

它把素材收进 `<P>/assets/`（录像用克隆或硬链接，大录像不占空间），写 `game.json`（一个三镜头的起点，每条录像在 `sources` 里，带检测出来的黑边裁切 `crop`，每张图在 `stills` 里）、`FACTS.md`、`STORY.md`、`CREDITS` 草稿和 `.gitignore`，然后盘点一遍：`out/inventory.md`（每条录像的时长、尺寸、帧率、有没有声音、裁切；每张图的尺寸、透明、猜的用途；每个文字文件的开头几行）和 `out/inventory.jpg`（所有图拼在一张上）。看这张图：哪张是主视觉，哪张是 Logo，哪些是立绘，哪些是哪个系统的截图。

在一帧上核对每个 `crop`（`look.py … --grid`，第 2 节）：只剩游戏画面，没有黑边、没有窗口框。截图常带一圈透明边（盘点会指出来并给出裁切）：用 `grab` 加那个 crop 来用，不然铺满时会透出底色（构建会警告）。

用户在聊天里贴的、或者你在页面上读到的商店页文字，存进 `<P>/assets/text/store.md`，写上网址和读取日期：`FACTS.md` 引用的就是它。

## 2. 找卖点镜头和那个真实数字：`scan.py`、`look.py`

```sh
$PY $K/tools/scan.py <P> play                           # 带时间码的接触表 + 场景表 → out/scan/play/
$PY $K/tools/look.py <P> play 6:08 --grid               # 一帧叠 100 px 网格：读坐标
$PY $K/tools/look.py <P> play 6:08 --rect 1300,1900,450,100              # 放大这一块：写的到底是什么
$PY $K/tools/look.py <P> play 6:15-6:20 --rect 1300,1900,450,100 --step 0.2   # 它怎么变：找准确的那一帧
```

`scan.py` 解码一遍录像，写出 `sheet-*.jpg`（每隔几秒一格，标 分:秒）、`scenes-*.jpg`（每个场景的第一帧和起止）和 `LOG.md`：一张时间码表，三栏空着：画面里是什么、能证明哪个卖点、有什么真实数字。边看边填。长场景（20 秒以上）多半是一段连续操作（交易、跑图、战斗）：细看。游戏常用淡入淡出换场，场景分数低：一个长场景里装着好几样东西时，用 `--scene 0.1` 再跑一遍。接触表和场景表的时间码用来定位；写 `in` 入点之前用 `look.py` 核对。

卖点来自商店页自己的话（简介里列着：跨城跑商、策略回合制、探索、招揽伙伴）。每个卖点找最能证明它的片段：UI 读得清、正在发生什么、没有半开的菜单。

**那个真实数字。** 找录像里一个会变的数：交易后的钱、伤害、等级、掉落、分数。用 `look.py --rect … --step` 逐帧读：变化前是多少、哪一帧落到最终值、**在那儿停多久**（后面一次买入可能又把它变掉）。每一项连同时间码写进 `FACTS.md`。装了 tesseract（带 `chi_sim`）时 `--ocr` 会顺便打印识别的字；以眼睛看到的为准。变化条可以框整个画面（`--rect 0,0,<宽>,<高>`）看很长一段：帧在 ffmpeg 里挑好、缩小。

## 3. 三个故事：`STORY.md`

填 `STORY.md`（模板在里面）：带时间码的卖点、那个真实数字，然后**三个故事方案**（每个几行：贯穿全片的手法、前两秒、节拍、声音）和各自的缺点，最后写选哪个、为什么。常见的几种：一个数字贯穿的一段旅程；角色群像（一个角色带一个玩法：只有录像里看得出谁做什么时才行，否则就是在编）；一个系统讲深；用游戏里的一本书或一页日志串起来。第一个想到的往往是俗套：从素材里挑。

## 4. 音乐、拍子和字幕牌材质：`beats.py`、`plate.py`、`fonts.py`

```sh
$PY $K/tools/beats.py <P> --scan          # 录像的声音每 20 秒估一次速度和拍点清晰度
$PY $K/tools/beats.py <P>                 # 选中的那一段（audio.start）对网格（audio.bpm）→ data/beats.json
$PY $K/tools/plate.py <P> play 6:08 --rect 2441,1404,585,101 --logo logo [--write]
$PY $K/tools/fonts.py <P> --list
```

- **音乐。** 挑一段拍子清楚的（清晰度 0.5 以上）、速度合适的（多数宣传片 110–160）、对白和界面音尽量少的。写 `audio.start` 和 `audio.bpm`，不带 `--scan` 跑 `beats.py`：它把网格铺到这一段的起音上（低频加权，分得开正拍和反拍；速度用整段拟合），打印拍点相对第 0 秒实际在哪、什么速度最合，起点或速度偏了半帧以上时给出该改成多少。照改、再跑，直到它说网格对得上；建议会收敛。它警告正拍和错半拍得分差不多时，听一下切点，或者换一段。片子的第 0 秒就是 `audio.start`，也是一个拍点；`game.json` 里任何地方写 `"4b"` 就是四拍。
- **这个系统自己的音乐拍子不清时**（散板的战斗曲、氛围探索曲：清晰度低于 0.4 左右），换一段拍子清楚的游戏音乐，从录像里取，或者用用户给的音乐文件（`audio.file`），并在确认点 1 说明：配这段音乐合不合适由用户定。不要手写一个音乐里没有的网格。
- **字幕牌材质。** 框一块有代表性的 UI 面板，连同边框（对话框、商店面板、标题条；坐标从 `look.py --grid` 读）。`plate.py` 从边缘往里读出外框和内描、面板上下两种颜色和字色，再取 Logo 的强调色；打印一段 `look`（`--write` 直接写进 `game.json`），存 `out/plate/swatch.jpg`：放大的面板、色块和一块示意字幕牌摆在一起。用眼睛校：它可能把铜框混进面板，或者读不出斜面、渐变的内描（读得不可靠时会提示）；对照色卡和放大的 UI（`look.py --rect` 框边缘），手动定颜色。UI 有铆钉、拉丝就开，没有就关（`rivetSize` 为 0、`brushed` 为 0）。字幕牌标题里的 `{x}` 用内描色（`plate.inner`），行动号召小字里的 `{x}` 用 `look.warm`：UI 的内描是银色、灰色时，从 UI 上自己的暖色高光里挑 `warm`。
- **字体。** `look.title.font` 配游戏的字形（STYLE.md §4）；`look.small.font` 一般用 `notosanssc`。

## 5. 镜头表：确认点 1

填 `game.json` 的 `shots`。所有时间都可以写秒或拍（`"4b"`）；时间码（`"6:07.6"`）是录像里的位置。

| 镜头字段 | 含义 |
|---|---|
| `id`、`beats`（或 `dur`） | 名字；长度（拍数，整拍保证每个切点在拍上） |
| `sound` | 切点上的音效：`whoosh`、`whoosh-long` |
| `layers[]` | 画面，可以前后接、也可以时间上重叠：`{"src": "play", "in": "7:30.0", "rate": 1}`（一段录像）或 `{"still": "keyart"}`；`from`、`to`（镜头内时间；`from` 默认 0，`to` 默认到镜头结束；后面的层盖住前面的） |
| `layers[].view` | `[x, y, w]`：开始时铺满画面的是源图上哪一块（默认居中铺满） |
| `layers[].moves[]` | `{"at", "dur", "ease", "zoom": z 或 [z0, z1], "focus": [x, y]}`（绕一点推近）或 `{"at", "dur", "ease", "view": [x, y, w]}`（推到一块区域）；推进 UI 时加 `sound: "swish"` |
| `plates[]` | `{"text": "跨城[跑商]", "at": 0.12, "to": …, "pos": "bottom"/"top", "size": 96, "sound": "pop"}`；`at: 0` 表示第 0 帧就在（钩子）；`[词]` 强调色，`{x}` 暖色 |
| `finale` | `crew`（`stills`、`every`："0.5b"）、`band`（`land`、`slide`：默认 1.25 拍，`land` 至少要在镜头里 `slide` 那么晚，否则横幅会在镜头开始前就滑起；`sound`）、`logo`（`still`、`at`、`sound`）、`cta[]`（`text`、`at`、`style`：`title`、`small`、`muted`；最多三行） |
| `card` | 库自己的片尾卡（`lines`、`land`）：**只给库的示范片**，用户的片子绝不加 |
| 顶层 | `title`、`name`（输出文件名前缀）、`fps`、`poster`（片中秒数）、`sources`、`stills`（裁切写在 `grab` 里）、`audio`、`look` |

照选定的故事一个镜头一个镜头写：

- **第 0 帧是封面**：主视觉（或游戏的标题画面），第一块字幕牌已经在上面（`"at": 0`）。主视觉上常印着 Logo：用 `view` 把它留在画外（Logo 在结尾大大地落地一次）。
- **一个镜头一个说法**，用能证明它的片段，用让它读得清的镜头：地方用慢推，UI 里的东西在拍点上推进（`"at": "1b"`，0.52 秒）。坐标是裁切后的游戏像素（`look.py --grid`）。
- **数字镜头**最长：录像加速到装得下那段操作（`rate` 1.5–2），推进计数，数字牌在数字落定之后（帧号由 `look.py` 给），然后从那一帧起接第二层原速（`"in"` = 落定那一刻，`"view"` = 推进后的那块），让数字在字幕牌被读的时候一直在。
- **字幕牌的时间。** 从擦开完（`at` 之后 0.36 秒）到镜头结束或它的 `to`，要有 汉字 ÷ 4.5 + 其他 ÷ 15 + 1.5 秒：4 个字 2.4 秒，7 个字 3.1 秒，"货钞 4351 → 14775" 2.6 秒。字幕牌一般放在镜头的第 0.12 秒，除非要先发生什么；实在不能少写字，就给镜头多一两拍。
- **数字停不住时。** 录像在落定后一秒内就走了（结算画面、淡出），就在同一块字幕牌下面接游戏自己的下一屏（胜利横幅、结算、"击败首领"提示）作后面的层，直到字幕牌读够时间；不要定格，也不要在字幕牌还在被读时切走。
- **收尾**：伙伴竖条从切点起按半拍擦入；横幅和 Logo 一起落在强拍上；行动号召一拍一行；最后一行要停够读的时间（"TapTap 搜索「游戏名」"约 3.7 秒）。

**拍数预算**（140 BPM，一拍 0.43 秒；别的速度按秒折算）：

| 片长 | 镜头和拍数 | 秒 |
|---|---|---|
| 15 秒 | 钩子 7 拍（第 0 帧就有字幕牌，最多 6 个字）· 数字镜头 12–14 拍（第 1 拍推进，落定后出数字牌，约 2.6 秒读字）· 收尾 12 拍（横幅、Logo、行动号召第一行同一拍落地，后两行各隔一拍，搜索那一行停约 3.7 秒） | 约 14.5 |
| 30–45 秒 | 钩子 8 · 三四个系统镜头各 8 · 数字镜头 20–23 · 双段 12 · 带伙伴的收尾 22–23 | 38–41 |

字幕牌的读字时间和 0.36 秒擦开都算在它所在的镜头里；三行行动号召从第一行到片尾大约要 9 拍。

- **要裁的静图**（截图或录像某一帧里的立绘）：写 `grab`：`from`、`t`、`crop`、`size`；`clips.py` 来做。

**给用户看** `STORY.md`（三个方案和选择）和镜头表：每个镜头的片段和时间码、字幕牌、数字那一刻的前后值、行动号召。**等用户点头。** 字和片段先改好再往下走。

## 6. 看样张：确认点 2

```sh
sh $K/tools/preview.sh <P> auto                 # 每个镜头三个时刻 → <P>/out/preview.jpg（REMOTE=1：在渲染台式机上截）
sh $K/tools/preview.sh <P> 0,5,8.5,12,17.5      # 或者自己挑片中秒数
```

它会切帧和静图（`clips.py`：已是最新的跳过）、切字体子集（`fonts.py`：第一次要下载字体，连 Noto Sans SC 约 25 MB，几分钟，要联网）、生成页面（`build.py`：提醒读字时间不够的字幕牌、不在 `FACTS.md` 里的数字、不是整拍的镜头；镜头露出素材边缘、一块字幕牌两个强调词就停）。每张都放大看：录像铺满；UI 读得清；字幕牌不挡这个镜头要说的东西；每块牌一个强调词；数字牌在数字落定之后出现、出现时数字还在画面上；伙伴一秒内到齐；Logo 完整、够大。

**把样张给用户看，等用户认可**画面。

## 7. 成片：确认点 3

渲之前告诉用户要多久：帧数 = 片长秒数 × 帧率；近几年的 Mac 3 个 worker 在这个风格上约每秒 25–50 帧（30 fps 的 40 秒片子渲一分钟以内，再加编码）；长片子用渲染台式机。

```sh
sh $K/tools/make.sh <P> v001                    # → <P>/<name>-v001.mp4 和 <P>/poster-v001.jpg
RENDER=remote sh $K/tools/make.sh <P> v002      # 画面在渲染台式机上渲（neo/render/remote.sh）
```

`make.sh` 切帧和静图、切字体、生成页面、导出画面事件、核对拍子网格（`beats.py`）、混音（`mix.py`：原声的那一段、合成音效、每个切点和落地对拍点的卡点核对、−14 LUFS）、按片子的帧率渲染、合成（`LEMO_COLOR=bt709`，不加颗粒）、跑 `readcheck`，再出海报和接触表（`out/contact.jpg`，每秒一帧）。每次重做都是新版本（`v002`……）。然后检查：接触表；数字那一刻和收尾的 0.2 秒序列（`node core/render/still.mjs <P> --range 16.8:18.2:0.2 --out <P>/out/strip`，再 `core/render/sheet.py`）；`mux.sh` 打印的响度；卡点表和母带的软削波那一行（某一下被削掉 6 dB 以上就太冲了：在 `mix.py` 的 `SOUNDS` 里调低它的增益）。新版和旧版在同一时刻对比：`$PY $K/tools/compare.py new.mp4 old.mp4 0,5,10 --out <P>/out/compare.jpg`。

渲染台式机收到的是去掉 `.mp4` 和 `out/` 的工程目录：帧（`frames/`，几百 MB）跟着过去，录像不过去。

**请用户完整看一遍、听一遍。** 声音只测过、没人听过：用户看过听过，片子才算完。

## 8. 交付

DIRECTOR.md §11：`<name>-vNNN.mp4`、`poster-vNNN.jpg`、`STORY.md`、`FACTS.md`、`CREDITS`（游戏素材属于谁、经谁授权；`fonts/fonts.json` 里的两种 OFL 字体；合成的音效），以及带 `game.json` 的工程。用户的片子不署 NEO-Cine，没有片尾卡。交付后 `frames/` 里的帧可以删（`clips.py` 能重做）。

## 出问题时

- **"镜头露出了画面外面"**：推拉露出了素材边缘：推得更近一点，或者把不动点挪离边缘。
- **"录像层 … 还没抽帧" / "帧和镜头表对不上"**：跑 `clips.py`（`make.sh`、`preview.sh` 会跑）。
- **渲染时 "缺帧 frames/…"**：帧被删了，或者 `clips.py` 之后镜头表又改过：再跑一遍。
- **卡点核对不过**：`beats.py` 会说是整体偏了（照它给的起点改 `audio.start`）还是在漂（速度不对）；只有一个切点不对，说明有个镜头不是整拍。
- **字幕牌读字时间不够**：少写字、字幕牌在镜头里提前，或者镜头多一拍。
- **字幕牌上的数和画面上的不一样**：用 `look.py --step` 看爽点之后的计数；在落定处把这一层拆开、后半段原速，或者早一点切。
- **字体**："两种字体都没有这些字"：两种字体都缺的字；换个说法，或者换字体（`fonts.py --list`）。
- **录像 60 fps、片子 30 fps**：`clips.py` 取最近的那一帧；要 60 fps 的片子就写 `"fps": 60`（帧多一倍）。
