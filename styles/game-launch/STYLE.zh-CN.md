# 游戏发布 Game Launch：风格说明

*来自库作者给一款独立 RPG 做 Demo 宣传片的过程，经开发者授权。英文版：[STYLE.md](STYLE.md)（代理读英文版）*

> 用一款游戏自己的素材做的发布短片：实机录像和官方美术铺满全画面，字幕牌用游戏自己界面的材质（它的边框、金属、铆钉、Logo 的颜色），镜头推进 UI，推到那个让人想玩的真实数字读得清，剪辑卡在游戏原声的拍子上。伙伴按拍擦入，Logo 落地，最后一屏说清楚去哪儿玩。
> 参考（只学语法）：主机和手游的商店页宣传片、Demo 公告（实机先行，一拍一个钩子，最后是 Logo 和平台）；把游戏自己的界面当作设计系统。不抄它们的画面、音乐、版式和字体，片子里也不提它们。

需要：库的核心工具（Node、ffmpeg 7+、无头浏览器和 `setup.sh deps` 装的 `.venv`）。游戏这边：一条实机录像（越长越好，几分钟的真实游玩）、主视觉、Logo（透明底的 PNG 最好）、有的话加角色立绘、商店页的文字，以及用户确认游戏是他的，或者他已获得开发者授权。字体由工具包下载（OFL）。其余都在 [`kit/`](kit/) 里：这个风格的片子照 [`PRODUCTION.zh-CN.md`](PRODUCTION.zh-CN.md) 一步步用它做。

## 1. 本质，以及它不是什么

- **实机画面是主角。** 游戏的真实录像和官方美术每一帧都铺满全画面：不留黑底，不加上下黑边，不把录像缩成色块上的一个小框。镜头永远不露出素材的边缘之外。
- **字幕牌是游戏做的。** 每块字幕牌都用游戏自己界面的材质：面板的颜色或渐变、外框和内描、铆钉或角饰、Logo 的强调色。每款游戏有自己的牌子，绝不是一条通用的下三分之一字幕条。
- **一个真实数字（或一次真实的爽点）贯穿全片。** 录像里确实发生的变化（一趟跑商货钞 4351 → 14775、一次伤害数字、一次升级、一次出金、一座基地建成）：片子一路走向它，推近到读得清，停住，再用一块字幕牌把它说出来。那一刻就是高潮。
- **推近到 UI 读得清。** 菜单、价目表、技能名要在画面里大到能读（正文在屏幕上约 26 px 以上，数字更大），不能只当花纹。
- **卡在游戏自己的拍子上。** 配乐是游戏原声的一段，每个切点、每次落地都在它的拍点上。
- **伙伴按拍擦入，Logo 落地，行动号召要具体：** 上线了什么（Demo、抢先体验、发售日）、在哪儿找（商店和要搜的字）、哪些平台。
- **不编任何东西。** 画面上的每个数字、功能和说法，要么录像里看得见，要么商店页、更新日志、开发者自己的帖子里写着（`FACTS.md`）。
- **每一帧都是时间的函数**，第 0 帧是一张完整的画面（主视觉加第一块字幕牌：平台拿它当封面）。

它不是 CG 预告片（不做游戏里没有的渲染场景），不是实况录像（没有大段不剪的游玩、没有摄像头、没有鼠标乱晃），不是讲游戏的动态图形片（没有暗底上漂浮的卡片、没有粒子），也不是模糊底图上的截图轮播。

## 2. 材质与渲染

- **录像变成帧，绝不用 `<video>`。** `kit/tools/clips.py` 把镜头表用到的每段录像，按片子自己的帧格切成静图：片子第 g 帧显示录像里离 `入点 + (g/fps − 层起点) × 速率` 最近的那一帧，而且只存镜头那一刻看得到的那一块（四周多留 3%），按画面分辨率存。页面在第 g0 + k 帧显示这一层的第 k 张。所以任何一帧都能单独渲、乱序渲、在任何机器上渲（Mac 和 Windows 渲染台式机出来一样）。帧是中间产物（`frames/`，不进 git），片段或镜头改了会重新切。
- **先裁录像。** 录屏常带黑边、窗口框或手机边框：`sources.<名>.crop` 一次裁掉，之后所有坐标（镜头、字幕牌取色、放大查看）都是游戏自己的像素。
- **镜头是每层一个变换**：源图上的一块（`view: [x, y, w]`），或者绕一个不动点推近（`zoom`、`focus`），带缓动，是 t 的纯函数。会露出边缘的推拉，构建时直接停下。
- **静图**（主视觉、立绘、Logo）是文件；从主视觉、截图或录像某一帧裁出来的，由 `clips.py` 按 `grab`（来源、时刻、裁切、尺寸）做，裁法写在镜头表里，随时能重做。
- **字幕牌**是 HTML：两种面板色之间的竖向渐变、外框、内描、两颗铆钉、一道硬投影（不模糊：游戏 UI 是锐利的），上面是标题字。收尾横幅和片尾卡用同一种金属，加一层很淡的斜纹拉丝。
- **帧率**跟录像走，默认 30 fps（录像是 60 fps、用户也想要时用 60）。库默认的 24 fps 会让 30 fps 的录像掉帧、重复帧。母带不加颗粒：录像有自己的质感。

## 3. 色彩逻辑

- **用游戏的配色，不用我们的。** 录像和美术保持原色：不调色、不加色调、不在标题下压暗（压暗截图上叠标题，是通用宣传片最明显的标志）。
- **字幕牌的颜色从游戏 UI 里取**（`kit/tools/plate.py`）：面板的上下两种颜色、外框、内描、字色。铆钉、角饰、拉丝只在 UI 有的时候加。
- **一个强调色：Logo 的颜色**（取它最饱和的色相）。每块字幕牌只给一个词，行动号召的关键词，别处不用。另一种暖色取自 UI 的金属：字幕牌上的符号（箭头）用内描色，行动号召里要搜的字用 `look.warm`（UI 上更亮的暖色高光，小字也读得清）。
- **不要辉光、光的渐变、紫蓝科幻渐变、玻璃卡片**，除非那就是游戏自己的 UI。

## 4. 字体与字幕牌

- **标题字：和游戏字形相配的 OFL 字体**（`kit/tools/fonts.py --list`）：Logo 是斜笔画、硬朗的动作和二次元 RPG 用得意黑；像素和复古游戏用站酷庆科黄油体；休闲、温馨的游戏用站酷快乐体；武侠、仙侠和剧情向用马善政毛笔楷书或思源宋体。字幕牌上 104 px，字距 0.02 em，一行。
- **小字：思源黑体 Noto Sans SC**（600），给行动号召的第二、三行。绝不用系统字体（苹方、冬青黑体、微软雅黑）：Mac 和 Windows 渲出来要一样。
- **一块牌子一个说法，两到八个字**，最多一个强调词（`[词]`）。说法是商店页用的动词加名词（跨城跑商、低买高卖、探索秘境），不是夸游戏的形容词。
- **数字牌**写录像里的前后两个数，强调色给后一个（货钞 4351 → 14775）。
- **位置：**左下（离左边、下边 150 px）或左上（离上边 130 px），哪个不挡这个镜头要说的东西就用哪个；游戏自己打在屏幕上的字（"胜利"、"自动战斗中"）本身就是字幕，不要再加。
- **读字时间**按库的规则（汉字 ÷ 4.5 + 其他 ÷ 15 + 1.5 秒），从字幕牌擦开完算起；`readcheck.mjs` 检查页面，构建时先预警。字在被读时不动：牌子擦开、字落定，然后一起停住。
- **默认没有字幕条、没有旁白：**字幕牌和游戏自己的声音撑起整支片子。

## 5. 运动质感

- **字幕牌入场：**clip-path 从左往右擦开，0.28 秒 `power3.out`；字晚 0.06 秒往右滑 30 px 落定，0.36 秒 `power3.out`。字幕牌跟着镜头在切点离开，不做退场动画。
- **镜头：**整个镜头一次慢推（`sine.inOut`，1.0 → 1.1–1.35），或者在拍点上一下推进 UI（`power3.inOut`，约 0.52 秒，到 1.5–3 倍），然后停住。推近不在镜头中途往回拉；自动战斗那种镜头可以从近处退到全景（1.18 → 1.0，`power3.out`）。
- **数字那一刻：**推进以后画面停在 UI 上，数字在里面变；写着数字的字幕牌在数字落定之后才擦开，绝不提前；落定以后录像可以回到原速，让那个数在画面上停够读的时间。
- **立绘：**每个角色一条竖条，按半拍从上往下擦开（`power3.out`，0.3 秒），里面的图同时下滑 60 px；竖条之间一道 3 px 的铜线。整组大约一秒内到齐，不留半屏空着。
- **收尾横幅**从左边滑入，`power4.in`，落在强拍上；Logo 同一帧落地（缩放 1.18 → 1，0.25 秒 `power4.out`）；行动号召一拍一行跟上。
- **速度：**录像可以比实际快（1.5–2 倍），把一趟买卖、一段跑图、一次建造塞进几秒；不能比实际慢，不能倒放。
- **没有闲置动作：**不漂、不呼吸、不晃；动来自镜头和游戏本身。

## 6. 镜头语法

画面就是游戏；片子加上去的只有镜头。下面是词汇表，不是路线。

| 镜头类型 | 画面 | 适合 |
|---|---|---|
| 钩子 | 主视觉，慢推向一个细节（飞艇、主角的脸），第 0 帧就有字幕牌 | 旅程从哪儿开始、你是谁 |
| 系统镜头 | 铺满全画面的实机片段，慢推，或推进 UI 上能证明说法的那一块 | 一个玩法：旅行、交易、建造、探索、战斗 |
| 数字镜头 | 推进一个计数，停住看它变，数字牌 | 爽点，全片高潮 |
| 双段 | 一个镜头两段短片（各一半），一块字幕牌跨两段 | 一个系统的两个时刻：选择和它的事件、手动战斗和自动战斗 |
| 伙伴 | 角色立绘竖条，按拍擦入 | 谁和你一起走 |
| 收尾 | 铁板横幅压在伙伴上，带 Logo 和行动号召 | 上线了什么、在哪儿、哪些平台 |

切点是拍上的硬切（换场前可以有一声风）；不做叠化，不用游戏里没有的形状做转场。相邻镜头不重复同一种动作；推进 UI 留给证据在 UI 里的镜头。

## 7. 声音

- **游戏自己的音乐：**原声的一段，从录像里截，或者用用户给的音乐文件，保持游戏自己的速度（`kit/tools/beats.py --scan` 列出整条录像各段的速度和拍点清晰度；`beats.py` 核对网格）。画面按这个网格剪；切点离检测到的拍点超过半帧，卡点核对就停。
- **录像里的界面音**跟着音乐一起来（点击、金币）：有帮助就留着（一次卖出），太杂就换一段。
- **几个代码合成的音效**放在画面事件上（`kit/tools/mix.py`）：换场前一声风、进战斗一声长风、推进 UI 一声短促的嗖、数字牌出现一声"啵"、Logo 落地一记低音冲击。不用采样库。
- **默认没有旁白**：说法写在字幕牌上。用户想要人声时照 TECHNIQUE.md §4 做，音乐在人声下压低。
- 母带用一个增益定到 −14 LUFS（`neo/audio/master.py`，再 `LEMO_COLOR=bt709` 跑 `mux.sh`）。

## 8. 这种媒介特有的动作

- **在 UI 里读到那个真实数字。** 在拍点上推进计数，停住看它涨，擦开一块"之前 → 之后"的字幕牌。*适合：*一次交易、一次收获、一次升级、一次抽卡结果、一圈最快圈速、一座城的人口。
- **用游戏做的字幕牌。** 字幕看起来就是游戏界面的一部分。*适合：*片子里的每个说法。
- **慢推进主视觉。** 第一帧是官方美术加一块已经在那儿的字幕牌，镜头飘向开启故事的那个细节。*适合：*钩子。
- **一个镜头里的两个时刻。** 选择和结果、手动战斗和自动战斗，各占半个镜头，一块字幕牌。*适合：*有两面的系统。
- **游戏自己的横幅就是字幕。** 游戏把字打在屏幕上时（自动战斗中、VICTORY、LEVEL UP），片子不再往上加东西。
- **伙伴按半拍擦入。** *适合：*队伍、角色阵容、名册。
- **横幅和 Logo 一起落地。** 铁板横幅在强拍上滑入，Logo 同一帧落地，一记低音，行动号召一行行跟上。*适合：*这个风格每一支片子的结尾。

新片子可以试的（工具包里还没有；在同一个时钟上做）：同一个地方的前后分屏（一座村子和它后来变成的城）；一个计数同时出现在两处；在世界地图上画出两座城之间的航线。

## 9. 这种媒介的陷阱

- **编造数字或功能。** 录像里看不到、商店页没写的，不上字幕牌。字幕牌上的每个数字都要在 `FACTS.md` 里（构建会查），附录像时间码或页面原话。
- **在压暗的截图上叠标题。** 字幕牌就是字的底；录像保持原样。
- **录像周围有黑框**，或者镜头推出了素材边缘（构建会停）。
- **Logo 缩在角落。** Logo 在横幅里大大地落地，一直留到最后。
- **字在被读时还在动**，或者数字牌比录像里的数字先出现。
- **装饰线穿过 Logo**（合缝、分隔线、闸门边），或者竖条之间的铜线穿过一张脸。
- **拼画面时留着大半屏空着**：伙伴按半拍擦入，大约一秒到齐。
- **字幕牌下面录像里的数字又变了。** 爽点之后也要看计数：后面一次买入可能让它变掉，字幕牌却还写着那个爽点（用 `look.py` 的变化条查）；回到原速，或者早一点切。
- **通用宣传片的摆设**：角标、游戏里没有的 HUD 框、三张卡并排、所有元素一起淡入上浮、辉光粒子、紫蓝渐变、玻璃卡片、米色纸面加衬线。
- **字幕牌用系统字体**（Mac 和 Windows 渲染台式机上不一样）。
- **权利。** 只用用户自己的游戏，或者用户已获开发者授权的游戏；商店页的文字和录像里的数字是事实，美术和音乐是开发者的（DIRECTOR.md §12）。`CREDITS` 写明它们属于谁、经授权使用。

## 10. 引擎

[`kit/`](kit/) 里的工具包把一款游戏的素材做成整支片子，[`PRODUCTION.zh-CN.md`](PRODUCTION.zh-CN.md) 是使用手册，带用户确认的三个点。看代码，这里不复述。

- 时间线和镜头：`kit/lib.py`（`plan`：镜头表 → 镜头、画面层、帧格、画面事件；`camera`：取景和推近合成每层一个仿射，对照素材边缘检查；读字规则）。
- 页面：`kit/page/template.html`（画面层、字幕牌、伙伴、横幅、Logo、行动号召、片尾卡，字幕牌材质是 CSS 变量），`kit/page/film.js`（库的页面约定；录像帧按帧号取；给 readcheck 的 `TEXTS`），`kit/page/tween.js`（入场是时间的纯函数，支持 clip-path）。
- 工具（`kit/tools/`）：`new_project.py`、`inventory.py`、`scan.py`、`look.py`、`beats.py`、`plate.py`、`clips.py`、`fonts.py`、`build.py`、`mix.py`、`preview.sh`、`make.sh`、`compare.py`。模板在 `kit/templates/`（`game.json`、`STORY.md`、`FACTS.md`）。
- 示范片（[`demo/`](demo/)）本身就是用工具包做的一个工程：`demo/game.json` 是它的全部镜头表。

## 11. 可变化的范围

每支片子自己定：游戏和它的素材、那个真实数字或爽点、三个故事方案和选择、哪一段原声和它的速度、字幕牌的材质（从这款游戏的 UI 里取：蒸汽朋克 RPG 是带铜框铆钉的铁板，像素游戏是像素描边的方框，武侠游戏是卷轴纸配毛笔字，温馨手游是圆角糖果色面板，只有游戏 UI 本来就是霓虹 HUD 才用霓虹边框）、标题字体、强调色（Logo 的）、长度（15 秒：钩子、数字镜头、收尾；30–45 秒：五到七个镜头）、各个系统的顺序、有没有伙伴段、行动号召的字和平台。

适用于任何有录像的游戏：二次元和剧情 RPG、像素和复古游戏、各类独立游戏、手游和抽卡游戏、策略和经营游戏、卡牌游戏、竞速和体育（数字是圈速或比分）。

- **结构：**一段旅程（出发 → 按玩家遇到的顺序过各个系统 → 爽点 → 伙伴 → 收尾）；一个系统讲深（同一个循环三个镜头，数字每次更大）；之前和之后（第一个小时和第十个小时，同一个地方变了样）。
- **开场：**第 0 帧就是主视觉加字幕牌；数字已经在屏幕上，再抛一个问题；游戏自己的标题画面。
- **结尾：**伙伴加带 Logo 的横幅；Logo 落在主视觉的天空上；最后一个实机镜头停在横幅下面。
